# Bases 视图（`〈成员〉/7-视图/检查报告库.base`）

把**报告页 / 汇总页的 frontmatter 当字段**做查询，输出表格。它属于 `7-视图/` 那一层（派生、可重生成）。

## 一句话：它是查询，不是清单 —— 归档时不碰

| | `5-指标/指标总表.csv` 等 | `检查报告库.base` |
|---|---|---|
| 本质 | **数据行**，归档时手写追加 | **查询**（filters + order + sort） |
| 新来一张单据 | 必须追加行 | **一个字节都不用改** |
| 谁在维护它 | 归档流程第 6 步 | frontmatter 本身（本来就是必填项） |

机制：Bases 跑在 Obsidian app 的 metadata cache（每个文件的属性解析结果）上 —— 文件一落盘、frontmatter 一解析，视图就是最新的。**没有「重建索引」这一步**，不加常驻内存、不用模型。

什么时候才需要动这个文件：① 字段名 / 类型改了（口径变了）；② 要加 / 改视图。两者都属于「改技能」。

## 五个视图（跟着库长，行数会变）

| 视图 | 过滤条件 | 用来回答 |
|---|---|---|
| 报告页清单 | `类型 != "检查活动"` | 所有单报告页：日期 / 类型 / 项目 / 机构 / 异常项 / 数值已入表 |
| 检查活动汇总页 | `类型 == "检查活动"` | 每次检查活动：活动名 / 来源 / 报告数 / 异常项 |
| 近10次血常规 | `项目.contains("血常规")` + `limit: 10` | 把 `血常规` 换成任何项目名，即得该项目近 N 次 |
| 影像与功能检查 | `类型 == "影像"` 或 `"功能检查"` | 只能看图、没有数值的那批 |
| 数值未入表清单 | `数值已入表 == false` | 这些页在指标总表里查不到，只能看原图与结论 |

首次落地时的行数取决于你自己的库，别把某个数字当恒定值。

## 取数命令

```
XDG_RUNTIME_DIR=/run/user/$(id -u) obsidian base:query \
  path="〈成员〉/7-视图/检查报告库.base" view="近10次血常规" format=csv
```

- `format=csv|md|json`；`json` 每行带 `path`（可直接用它定位文件）。
- 需要 app 在跑；不可用就按 `SKILL.md` §检索 的降级口径直接读库文件，不重试、不启 GUI。
- 实测 4 ms 量级，回的是**表行**，不进正文 —— 「常用关键词命中一大片」这类问题在视图这条路线上不存在。
- `obsidian base:views` 要 app 里有「当前文件」才不报错（无头会话必报 `No active file`）—— 只用 `base:query`，别用 `base:views` 探活。

## 依赖的字段（视图不对先查这里）

| 字段 | 谁在用 |
|---|---|
| `tags` 含 `检查报告` | 全局过滤（报告页与汇总页都带这个 tag） |
| `类型` | 报告页与汇总页的区分、影像/功能检查筛 |
| `项目` | 按项目查（一张单据多项目时用 `+` 连接 → 用 `contains()`，**不能**用 `==`） |
| `日期` | 排序、读数 |
| `机构` `检查活动` `活动` `来源类型` `报告数` | 展示列 |
| `异常项` | 展示列（数字，可空） |
| `数值已入表` | 「未入表清单」筛（布尔） |

缺字段的表现是**单元格留白，视图不报错** —— 所以筛出来的行数对不上时，先按上面这张表核 frontmatter。

## 改 / 加视图

- 文件在库里（7-视图 是派生层），可以直接改；改完 `git add` 该文件提交。
- 加一个视图 = 复制一个 view 块，改 `name` / `filters` / `order`：

```yaml
  - type: table
    name: 视图名
    limit: 10                     # 可选
    filters:                      # 也可是单条字符串
      and:
        - '项目.contains("肝功")'
    sort:
      - property: 日期
        direction: DESC
    order:
      - 日期
      - 机构
      - file.name
```

- 改完**必须实测**：跑 `base:query`，确认不报 YAML/表达式错误，且行数对得上（拿 `search_files` 或 CSV 的数当对照）。
- 语法与函数全表：Obsidian 官方帮助（`help.obsidian.md/bases/*`）＋ 官方 Agent Skills（`github.com/kepano/obsidian-skills` → `skills/obsidian-bases`）。

## 边界

- 只认 **markdown 的 frontmatter**：`5-指标/指标总表.csv` 的行、`4-就医记录` 正文表格的行 **不进视图** —— 统计照旧走 CSV，找原话照旧走全文检索。视图是第三层：报告 / 活动级的字段视图，不替代前两层。
- 视图不写库、不改数据：只读 frontmatter。

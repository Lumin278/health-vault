# 10-血糖数据

一次**动态血糖监测（CGM）**监测期 = 一个文件夹：`〈监测首日〉-动态血糖监测`（如 `2026-09-13-动态血糖监测`）。

```
10-血糖数据/
└── 2026-09-13-动态血糖监测/
    ├── YYYY-MM-DD_动态血糖监测_AGP报告.pdf        设备 / App 出的评估报告（原样存）
    ├── 〈起始〉至〈结束〉_血糖打点值_合并事件.xlsx  打点原始值 + 事件标签（合并后的主数据）
    ├── 〈起始〉至〈结束〉_血糖打点值_合并事件.csv   同上，纯文本版
    └── YYYY-MM-DD_动态血糖监测_事件簿.csv          饮食 / 饮料 / 不适事件（可并入打点值，见下）
```

## 与相邻目录的边界

| | `5-指标` | `8-体重管理` | 本目录 |
|---|---|---|---|
| 数据来源 | 有检验报告的临床数值 | 自测体脂秤 | 自戴 CGM 设备 |
| 频率 | 一年几次 | 一天几次 | 每 3 分钟一个点，连续十几天 |
| 体积 | 几百行 | 几百行 | 单次监测期七千多行 |
| 结构化总表 | ✅ | ✅ | ❌ 只存原始文件 |

- **不建** `2-检查报告` 活动目录、**不加**就医记录行、**不进** `5-指标` —— 与 `8-体重管理` 同一口径：设备自戴自测，没有医院、没有医生、没有申请单。
- 报告里那些 TIR / TAR / TBR / MG / GMI / CV / LAGE 等**判定值与统计量不进任何总表** —— 它们是设备按自家公式算出来的，本库只原样存着，不拆成行、不做二次判定（`5-指标` 明文规定「定性判定值不进表」）。
- 想给医生看：直接把本文件夹里的 PDF 给他，或按 `SKILL.md` §面向医生的 PDF 出一份脱敏的。

## 放什么

- 设备 / App 出的**报告 PDF**（含 AGP 图、每日概况、总体指标、指标解释）—— 原样存，**不改写、不裁剪**。
- 设备的**逐点原始值**（CSV / XLSX）—— 原样存或合并事件标签后存。
- 本人**饮食 / 饮料 / 不适事件簿** —— 与打点值同放（合并成一列或独立 CSV 都行），让「吃了什么 → 血糖怎么动」能对照着看。

## 文件命名

| 内容 | 命名 | 说明 |
|---|---|---|
| 设备报告 | `YYYY-MM-DD_动态血糖监测_AGP报告.pdf` | 日期 = **报告生成日**（设备自己印的生成日期） |
| 打点数据 | `〈起〉至〈止〉_血糖打点值_合并事件.xlsx` | 起止 = 监测首末日 |
| 事件簿 | `YYYY-MM-DD_动态血糖监测_事件簿.csv` | 日期 = 录入 / 导出日 |

文件夹名用**监测首日**、报告文件名用**生成日** —— 一个管排序（按名字排就是一次次监测期），一个管这份报告是哪天出的。

## 派生说明页（可选）

文件夹里可以放一页 `YYYY-MM-DD-动态血糖监测.md`，记这次监测期的事实：起止日期、设备型号、探头值间隔与条数、报告里的总体指标（照录）、事件条数与时间对齐情况、待核对项。**只写事实与口径，不写解读、不写建议、不写「别删它」这类提醒。**

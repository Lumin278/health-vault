# 库的规格（建库 / 自查用）

规则口径在 `SKILL.md`；本文件只描述**库长什么样**。

## 目录树

```
〈库根〉/                          ← Obsidian 打开这一层
├── AGENTS.md                    铭牌（生成物：这是谁的库 / 结构 / 规矩在技能里）
├── .gitignore
├── 8-知识库/zz-项目名规范.md        受控词表（数据：项目名 / 指标名 / 机构名 / 体重管理指标名 / 药品管理类 / 血糖监测类）
└── 〈成员〉/
    ├── 1-基本信息/基本信息.md     姓名 / 过敏史 / 慢病 / 紧急联系人（基准线，只读）
    ├── 2-检查报告/               〈YYYY-MM-DD-机构-活动〉/{汇总页.md, 报告/, attachments/}
    ├── 3-不适记录/不适记录.md     四列：日期 / 不适的感受 / 我怎么处理的 / 持续多久
    ├── 4-就医记录/               就医记录总表.md（唯一手写源）+ YYYY.md 年子表（派生）
    ├── 5-指标/指标总表.csv        临床数值长表
    ├── 6-用药/用药流水.md         顶部「当前在服」表 + 按药分节时间线
    ├── 7-视图/                   主档案.md / 用药记录.md / 化验指标追踪.md / 检查报告库.base（派生，可重生成）
    ├── 8-体重管理/体重管理总表.csv 自测体态长表
    ├── 9-药品管理/药品管理表.csv   库存表（UTF-8 带 BOM）
    ├── 10-血糖数据/              〈监测首日〉-动态血糖监测/{报告 PDF, 打点值 CSV/XLSX, 事件簿}
    └── attachments/             待归类原图
```

库里**不放**技能、模板、规矩、说明文件（README）—— 只有数据 + 词表 + 铭牌这一份「给 AI 读的东西」。
各目录的说明在技能 `references/vault-dirs/`；用药知识在技能 `knowledge/用药/`。

```markdown
## 规矩在哪
所有口径（怎么写、怎么判断、字段格式、命名规范）都在 **health-vault 技能**里 —— 本库只有数据，不含规矩。

- **Hermes Agent**：技能已装载（`~/.hermes/skills/health/health-vault/`），按技能干活；cwd 在库内直接写，库外先问。
- **其他 agent（Codex / Cursor / Claude Code / Copilot…）**：先取到技能本体（仓库根就是技能根：`SKILL.md` + `references/` + `templates/` + `scripts/`），读 `SKILL.md` 后按它干活；本库的目录与列格式与技能一致。
- **没有这个技能时：不要直接改本库文件** —— 先把技能装上或读进来。

## 成员
当前：〈成员〉。新增成员 = 库根并排建一个同名目录（结构同上），不要复制 `8-知识库/` 与技能。
```

## 建库

```
python3 scripts/init_vault.py --dest 〈库路径〉 --member 〈姓名〉
```

Windows 上没有可用的 `python3` 时，改用 `python` 或 `py -3`。

（脚本从 `assets/skeleton/` 复制空骨架、替换成员名、写铭牌、`git init` 并首次提交）

成员名必须是单个可跨平台同步的目录名；路径分隔符、Windows 保留设备名等会被拒绝。`--force` 只补缺失文件，不覆盖已有文件；只有 `--plaque-only` 会重写 `AGENTS.md`。
